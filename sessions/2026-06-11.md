# Session — 2026-06-11

## Goal
Riley wanted to stop the manual ritual of: open terminal → `cd` into a `C:\Dev` project →
launch `claude` → ask Claude to start the app. Asked for a little desktop app with clickable
tiles, one per project, that does all of it automatically.

## Decisions (asked up front)
- **Tile action:** Both — launch `claude` in the folder AND hand it an initial prompt to auto-start the app.
- **Tech:** PowerShell GUI, zero-install. (Later replaced — see below.)

## What was built
A tile launcher living in `C:\Dev\launcher\`. Final architecture is a **standalone .NET
WinForms exe** (`DevLauncher.exe`) that reads tiles from `apps.txt` and, on click, opens a
named Windows Terminal tab in the project folder running `claude '<prompt>'`.

10 tiles: chektwo, hivemind, mixotrophic, Aithena-Admin, aithena-llm, aquasignal,
tpo-dashboard, blue-aqua-v2, muse, love-in-motion.

## How it evolved (3 iterations, each fixing a real bug found by testing)
1. **PowerShell + WPF** (`AppLauncher.ps1`) launched via `Launch.vbs` + desktop shortcut.
   - Headless build test caught a real bug: `x:Name` used but `xmlns:x` not declared → XAML
     parse failure. Fixed by adding the namespace. Verified all 10 tiles build.
   - Launch command Base64-encoded (UTF-16LE) as `-EncodedCommand` to dodge quoting hell.
2. **Tab naming** — `claude` overwrites the WT tab title on start. Added `--title` +
   `--suppressApplicationTitle`, plus `$Host.UI.RawUI.WindowTitle` as a fallback.
3. **Taskbar pinning broke** — pin captured *PowerShell*, not the launcher, because the
   visible window was owned by `powershell.exe` (the exe just spawned PS and exited).
   **Rewrote as a true standalone WinForms exe** so the window belongs to `DevLauncher.exe`.
   Confirmed: process = `DevLauncher`, window title "Dev Launcher" → pins correctly.
   Also moved the tile list out to `apps.txt` so edits don't need a recompile.

## Verified
- Script syntax (PS tokenizer) + headless WPF build (10 tiles, correct paths).
- EncodedCommand decodes to the exact intended PowerShell command.
- WinForms exe runs as its own process with its own window/identity.
- Live WT test proved `--suppressApplicationTitle` holds the tab name against an override attempt.

## Known / left to the user (Windows blocks automation)
- **Pinning is manual.** Win11 24H2 returns `Access denied` for programmatic taskbar AND
  Start pinning. User unpins the wrong PowerShell pin, then right-clicks the running
  Dev Launcher icon → Pin to taskbar.
- A few tile prompts are best-guesses where the run command wasn't obvious (tpo-dashboard,
  blue-aqua-v2, muse, aithena-llm) — they tell Claude to read the repo and figure it out.
- Offered but not yet done: pre-allowing the dev commands in Claude settings so tiles never
  stop to ask permission on first run.

## Files
- `DevLauncher.exe` / `DevLauncher.cs` — the app + source (WinForms).
- `apps.txt` — editable tile list.
- `DevLauncher.ico` — generated icon.
- `AppLauncher.ps1`, `Launch.vbs` — legacy PowerShell version, unused.
- Shortcuts on Desktop + Start Menu point at the exe.
